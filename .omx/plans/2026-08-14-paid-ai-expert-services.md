# 유료 AI 전문가 서비스 실행 계획

## 목표

준비도 진단의 55개 답변과 사용자의 추가 입력을 바탕으로 7개 AI 전문가와 4개 패키지를 판매하고, 결제 후 GPT-5.6 Sol이 조사·분석·실행계획을 생성하는 흐름을 제공한다.

## 최소 설계

1. 기존 PortOne 주문·환불 흐름을 재사용하고 주문에 `ai_agent` 유형만 추가한다.
2. 상품은 코드의 정적 카탈로그로 관리한다. 사람 전문가 DB 카탈로그와 분리해 공급자 정산을 만들지 않는다.
3. 결제 완료 시 주문별 AI 작업공간을 만들고, 필수정보 → 최대 2회 보완질문 → 가정 확인 → 보고서 생성 순서로 진행한다.
4. 사용자가 `모름`을 선택하면 공개자료와 유사사례를 사용하되 사실과 가정을 분리하고, 법률·규제·계약 효력과 실제 관계는 `사람 검증 필요`로 남긴다.
5. 모든 상품은 하나의 구조화 보고서 계약과 실행 엔진을 공유한다. 상품별 차이는 지시문·필수입력·산출물뿐이다.

## 구현 순서와 검증

- 정적 상품 카탈로그: 7개 단건 + 4개 패키지, 고유 ID·가격·포함 에이전트를 단위 테스트한다.
- 주문 분기: AI 주문은 공급자·서비스 FK 없이 전액 플랫폼 매출로 저장되는지 테스트한다.
- DB: `orders` AI 유형과 `ai_agent_runs` 상태·토큰·원가 필드를 추가한다.
- 작업공간: 입력 감사, 추가질문 2회 제한, 생성 1회 + 사실 정정 재생성 1회를 서버에서 강제한다.
- Sol 실행: 구조화 출력, URL 출처 허용목록, 프롬프트 인젝션 경계, 비용 산식 테스트를 적용한다.
- UI: `/services` → `/services/[id]` → 결제 → `/orders/[id]` 작업공간 → 보고서 다운로드를 한 흐름으로 연결한다.
- 전체 검증: `npm test`, `npm run typecheck`, `npm run build`, `git diff --check`, 프로덕션 스모크 테스트.

## 운영 경계

- AI는 실제 인터뷰, 파트너 접촉, 규제 승인, 법률·세무·계약 판단을 완료했다고 표현하지 않는다.
- 결제 전에는 모델 호출을 하지 않는다.
- 같은 주문의 동시 생성과 허용 횟수 초과 호출은 DB 상태 비교로 차단한다.
- 모델·도구·결제 비용을 주문별로 기록해 80% 공헌이익률 가설을 검증한다.
