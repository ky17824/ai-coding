# 대시보드 응답 해석·단계 그래프 설계 및 구현 계획

- 작성일: 2026-08-10
- 상태: 제안·검토 단계 (코드 변경 전)
- 범위: 창업자 대시보드의 최신 진단 응답 가시화

## 1. 결론

현재의 **“먼저 해결해야 할 선결 조건”** 아래에 다음 두 요소를 하나의 섹션으로 추가한다.

1. **현재 단계 응답 그래프**: 준비 1단계·준비 2단계·준비 3단계 중 이번 진단에서 멈춘 단계를 기본으로 보여준다.
2. **내 응답 해석 목록**: 각 질문, 실제 선택 답변, 답변 단계의 의미, 통과 여부, 보완 행동, 제출 증거를 보여준다.

그래프는 레이더 차트가 아니라 **항목별 가로 누적 막대그래프**를 권장한다. 현재 단계의 질문 수가 많고 답변이 1~4의 순서형 값이므로, 레이더 차트는 읽기 어렵고 면적이 실제 점수처럼 오해될 수 있다. 가로 누적 막대는 각 항목에서 1·2·3·4단계 답변이 차지하는 배점 비중과 단계 통과에 인정되는 3·4단계 비중을 동시에 보여줄 수 있다.

새 차트 패키지, 새 API, DB 마이그레이션은 필요 없다. 저장되어 있는 최신 응답과 현재 채점 함수를 그대로 재사용한다.

## 2. 사용자 요구사항 요약

- 창업자가 자신이 어떤 질문에 답했는지 한눈에 확인할 수 있어야 한다.
- 선택한 답변 문구를 원문 그대로 확인할 수 있어야 한다.
- 답변이 현재 준비도에서 무엇을 뜻하는지 이해할 수 있어야 한다.
- 통과, 보완 필요, 필수 선결 조건을 구분할 수 있어야 한다.
- 현재 단계에 해당하는 질문과 답변 결과를 하나의 그래프로 파악할 수 있어야 한다.
- 결과 확인 후 기존 **AI GTM 계획 만들기**로 자연스럽게 이동할 수 있어야 한다.

## 3. 현재 구현 확인

- 대시보드는 최신 진단의 종합 점수, 단계별 점수, 선결 조건만 조회하며 개별 응답은 조회하지 않는다: `app/dashboard/page.tsx:23-29`, `app/dashboard/page.tsx:88-113`.
- 진단 제출 시 개별 답변은 `readiness_answers`에 `question_id`, `level`, 증거 종류·내용으로 이미 저장된다: `app/api/assessments/route.ts:59-89`, `supabase/migrations/001_initial.sql:29-50`.
- 선택한 답변 문구는 질문의 `options[level - 1]`로 정확히 복원할 수 있고, 질문에는 보완 행동과 증거 기준도 이미 있다: `lib/intake-questions.ts:99-115`.
- 답변 단계의 의미는 1 미인지, 2 인지·계획, 3 실행·사례, 4 반복·확인이고, 3단계부터 통과 점수로 인정된다: `lib/intake-questions.ts:1-13`, `lib/intake-questions.ts:41-42`.
- 단계 통과는 가중 점수 80% 이상이면서 필수 문항 미통과가 없어야 한다: `lib/readiness.ts:71-101`.
- 관리자 화면에는 개별 답변을 조회하고 질문과 연결하는 최소 패턴이 이미 있다: `app/admin/companies/[id]/page.tsx:36-43`, `app/admin/companies/[id]/page.tsx:60`.

## 4. 제안 화면 구조

삽입 위치는 선결 조건 배너 바로 아래, AI GTM 계획 섹션 바로 위로 한다. 사용자가 먼저 자신의 응답과 의미를 이해한 후 보완 계획을 만들게 하기 위함이다.

```text
[먼저 해결해야 할 선결 조건]

[내 응답 진단 — 현재 단계: 준비 1단계]
  통과 7 | 보완 필요 8 | 필수 선결 조건 3

  [현재 단계 응답 그래프]
  글로벌 진출 관점     1단계 ██  2단계 ███  3단계 ████  4단계 █
  인적·운영 자원       1단계 ███ 2단계 ██   3단계 ██    4단계 █
  가치제안·국내 PMF    ...
  목표국가·초기 고객군 ...

  3·4단계 답변만 단계 통과 점수로 인정 · 현재 62% / 통과 기준 80%

  [전체] [필수 선결 조건] [보완 필요] [통과]

  Q01 질문 원문
  내 답변: 선택한 보기 원문
  의미: 필요성은 알고 있으나 실행 또는 증거가 부족합니다.
  상태: 보완 필요
  다음 행동: 질문에 정의된 action
  완료 증거: 제출한 증거 또는 질문에 정의된 followUp

  [AI GTM 어시스턴트와 보완 계획 만들기 →]
```

### 단계 선택

- 기본 탭은 **현재 멈춘 단계**다.
- 이미 답변한 이전 단계가 있으면 탭으로 다시 볼 수 있다.
- 아직 답변하지 않은 미래 단계는 표시하지 않는다.
- 세 단계를 모두 통과했다면 준비 3단계를 기본으로 보여주고 이전 단계 탭을 제공한다.

## 5. 그래프 설계

### 권장 그래프: 항목별 가로 누적 막대

- 세로축: 현재 단계에 속한 진단 항목. 예: 준비 1단계는 글로벌 진출 관점, 인적·운영 자원, 가치제안·국내 PMF, 목표국가·초기 고객군.
- 가로축: 해당 항목 전체 배점 100%.
- 구간: 1단계, 2단계, 3단계, 4단계 답변의 배점 비중.
- 통과 인정: 3·4단계 구간에 “단계 통과 점수 인정” 범례를 붙인다.
- 상단 요약: 현재 단계의 공식 점수와 80% 통과 기준을 함께 표시한다.
- 필수 문항: 막대만 색으로 표시하지 않고, 해당 질문 목록에 “필수 선결 조건” 텍스트 배지를 함께 표시한다.

### 색과 문구

| 답변 단계 | 화면 의미 | 그래프 표현 |
| --- | --- | --- |
| 1 미인지 | 아직 검토하거나 시작하지 않음 | 중립 회색 |
| 2 인지·계획 | 필요성은 알지만 실행·증거가 부족함 | 주황 |
| 3 실행·사례 | 실제 실행 경험이 있어 통과 점수로 인정 | 연한 초록 |
| 4 반복·확인 | 반복 실행 또는 외부 확인이 된 강점 | 진한 초록 |

그래프 아래에 동일 내용을 숫자와 텍스트로 제공해 색상만으로 의미를 전달하지 않는다.

## 6. 질문별 해석 규칙

AI가 질문마다 새 설명을 생성하지 않고 기존 진단 규칙을 결정적으로 해석한다. 대시보드 로딩 속도, 비용, 일관성을 지키고 AI는 실제 보완 계획 수립에만 사용한다.

| 조건 | 상태 | 표시할 의미 |
| --- | --- | --- |
| `level < 3`이며 필수 문항 | 필수 선결 조건 | 현재 단계 통과를 막고 있으며 우선 해결해야 함 |
| `level < 3`이며 일반 문항 | 보완 필요 | 필요성 인지 또는 준비 수준이 실행·증거 단계에 미달함 |
| `level === 3` | 통과 | 실제 실행 사례 또는 증거가 있어 단계 점수로 인정됨 |
| `level === 4` | 강점 | 반복 실행 또는 외부 확인이 된 상태로 단계 점수에 인정됨 |

각 질문 행에는 다음을 표시한다.

- 질문 원문과 문항 번호
- `question.options[level - 1]`에서 복원한 실제 선택 답변
- 위 표에 따른 답변 의미
- 필수 선결 조건·보완 필요·통과·강점 상태
- 미통과 문항은 `question.action`을 다음 행동으로 표시
- 제출 증거가 있으면 `evidence_value`, 없으면 `question.followUp`을 완료 증거 안내로 표시

## 7. 데이터 흐름

1. 조직에 속한 최신 진단을 현재 방식대로 조회한다.
2. 최신 진단 ID로 `readiness_answers`를 조회한다.
3. DB 응답을 `INTAKE_QUESTIONS`와 `question_id`로 연결한다.
4. 기존 `calculateReadiness`를 다시 호출해 현재 단계와 공식 통과 결과를 동일한 규칙으로 계산한다.
5. `INTAKE_ITEMS`로 현재 단계 질문을 묶어 그래프 데이터를 만든다.
6. 질문 원래 순서로 응답 해석 목록을 출력한다.
7. 기존 `/assistant/{assessment.id}` 링크를 섹션 마지막 행동 버튼으로 재사용한다.

보안상 관리자 클라이언트는 행 수준 보안(RLS)을 우회하므로, 최신 진단을 먼저 현재 사용자의 `organization_id`로 제한하고 그 진단 ID에 해당하는 응답만 조회한다.

## 8. 구현 단계

### 1단계 — 응답 조회 추가

- `app/dashboard/page.tsx:23-29`의 조직별 최신 진단 조회는 유지한다.
- `app/dashboard/page.tsx:48-59`의 병렬 조회에 최신 진단 ID로 제한한 `readiness_answers` 조회를 추가한다.
- 조회 필드는 `question_id,level,evidence_kind,evidence_value`로 제한한다.
- 레거시 0단계 값이나 질문 정의에서 사라진 ID는 화면 오류 대신 “이전 진단 응답”으로 안전하게 처리한다.

### 2단계 — 화면용 결과 계산

- `lib/readiness.ts:22-25`, `lib/readiness.ts:71-163`의 기존 질문 필터와 채점 함수를 재사용한다.
- 최소한의 순수 함수 하나로 다음 화면용 데이터만 만든다: 현재 표시 단계, 항목별 1~4단계 배점 분포, 통과·보완·필수 조건 수, 질문별 선택 문구와 상태.
- 새 점수 공식을 만들지 않는다. 단계 점수와 통과 판정은 반드시 `calculateReadiness` 결과를 사용한다.

### 3단계 — 대시보드 섹션 추가

- `app/dashboard/page.tsx:111-115` 사이에 **내 응답 진단** 섹션을 배치한다.
- 질문 목록은 기본적으로 현재 단계만 출력하고 `<details>`로 펼쳐 보게 한다. 관리자 화면의 기존 패턴을 참고하되 사용자용 해석과 행동을 추가한다: `app/admin/companies/[id]/page.tsx:60`.
- AI 계획 버튼은 기존 `app/dashboard/page.tsx:121-123`의 경로와 문구를 재사용한다.

### 4단계 — CSS 기반 그래프와 반응형 처리

- `app/globals.css:1350-1370`의 단계 막대와 `app/globals.css:2252-2265`의 meter 패턴을 재사용한다.
- 누적 구간과 상태 배지에 필요한 클래스만 추가한다. 새 차트 의존성은 추가하지 않는다.
- `app/globals.css:2876-2879`의 모바일 단일 열 규칙에 맞춰 620px 이하에서 항목명, 막대, 수치를 세로 배치한다.
- 그래프는 의미 있는 목록 구조, 텍스트 범례, `aria-label` 또는 `role="img"` 설명을 제공한다.

### 5단계 — 검증

- 순수 데이터 변환 함수에 최소 테스트를 추가한다.
- 타입검사, 전체 테스트, 프로덕션 빌드를 실행한다.
- 준비 1단계 실패, 준비 1단계 통과·준비 2단계 실패, 세 단계 통과, 레거시·누락 응답의 네 가지 대시보드를 확인한다.

## 9. 인수 기준

1. 최신 진단이 있으면 선결 조건 배너 아래에 **내 응답 진단** 섹션이 보인다.
2. 현재 멈춘 단계가 기본으로 선택되고 아직 답하지 않은 미래 단계는 노출되지 않는다.
3. 표시된 모든 질문에 질문 원문, 실제 선택 답변, 답변 의미, 상태가 보인다.
4. 1·2단계 일반 문항은 보완 필요, 1·2단계 필수 문항은 필수 선결 조건, 3단계는 통과, 4단계는 강점으로 표시된다.
5. 그래프는 현재 단계 항목별로 1~4단계 답변의 가중 배점 분포를 표시하고, 3·4단계만 통과 점수에 인정된다는 설명을 제공한다.
6. 그래프의 공식 단계 점수는 `calculateReadiness` 및 기존 `domain_scores` 값과 일치한다.
7. 제출 증거가 있으면 표시하고, 없으면 빈 영역 대신 완료에 필요한 증거 안내를 표시한다.
8. AI 계획 버튼은 해당 최신 진단의 `/assistant/{assessment.id}`로 이동한다.
9. 360px 폭에서 가로 스크롤 없이 읽을 수 있고 키보드로 질문 상세를 열 수 있다.
10. 다른 조직의 답변은 조회되거나 표시되지 않는다.
11. 개별 응답이 없는 이전 진단도 대시보드 전체를 깨뜨리지 않고 안내 문구를 표시한다.

## 11. 위험과 완화책

- **질문 정의 변경으로 과거 답변 문구가 달라질 수 있음**: 현재는 정적 질문 ID로 복원한다. 실제 설문 버전이 바뀌는 시점에만 `questionnaire_version` 저장을 별도 도입한다.
- **그래프 점수 오해**: “준비도” 같은 포괄 표현 대신 “단계 통과 인정 답변 비중”이라고 명시하고 3·4단계 인정 규칙을 함께 표시한다.
- **긴 질문 목록**: 현재 단계만 기본 표시하고 상태 필터 및 접기 UI를 사용한다.
- **관리자 클라이언트의 조직 경계**: 사용자 조직으로 제한한 최신 진단 ID를 기준으로만 응답을 조회한다.
- **레거시 응답 수준**: 1~4 범위 밖의 값은 계산에서 제외하고 이전 진단 안내를 표시한다.
