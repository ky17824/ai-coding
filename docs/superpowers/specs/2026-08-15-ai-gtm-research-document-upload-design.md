# AI GTM 사전조사 사용자 자료 업로드 설계

## 목적

AI GTM 어시스턴트에서 사용자가 보유한 PDF·PNG·JPG 자료를 최대 3개까지 제출하고, 자료에서 정제한 사실과 수치를 현재의 시장·경쟁 사전조사에 반영한다. 무료 사전조사는 사용자가 플랫폼의 분석 가치를 충분히 경험하도록 제공하되, 원문이 공개 웹 검색이나 검색 대상 사이트에 전달되지 않도록 한다.

유료 AI 전문가 서비스와의 경계는 유지한다. 무료 기능은 자료 기반 예비 시장·경쟁 조사, 근거 공백과 다음 검증 과제까지 제공한다. 반복 질의, 분야별 심층 보고서, 상세 실행계획과 사실 정정 재생성은 유료 AI 전문가 서비스의 범위로 남긴다.

## 범위

### 포함

- AI GTM 어시스턴트 입력 영역의 자료 업로드·목록·삭제 UI
- PDF·PNG·JPG, 파일당 4MB, 최대 3개 제한
- 기존 Supabase `evidence` 비공개 버킷 재사용
- 검색 도구가 없는 OpenAI 요청을 통한 원문 구조화
- 이메일·전화번호·URL·긴 식별번호 제거와 고객·파트너명 익명화
- 정제된 자료 원장을 시장동향·경쟁구도·시장규모 조사 입력에 반영
- 조사 화면과 HTML 보고서에 사용자 자료 반영 내역 표시
- 자료 변경 시 기존 조사 캐시 무효화
- 개인정보처리방침과 한·영문 안내문 갱신

### 제외

- 새 벡터 DB 또는 사용자별 OpenAI Vector Store
- DOCX·XLSX·PPTX·ZIP 지원
- OCR·PDF 파서용 신규 패키지
- 사용자가 업로드한 원문을 공개 웹 검색 요청에 포함하는 동작
- 무료 기능에서 제공하는 반복 상담이나 전문 분야별 최종 실행보고서

## 사용자 경험

AI GTM 어시스턴트의 창업자 입력 폼 하단, 사전조사 버튼 바로 위에 `보유 자료 반영` 블록을 둔다.

- 안내: `PDF·PNG·JPG, 파일당 4MB, 최대 3개`
- 개인정보 안내: `원문은 비공개 분석에만 사용하고 공개 웹 검색에는 보내지 않습니다. 분석 후 원문은 삭제하고 정제된 사실만 저장합니다. 공개 권한이 없는 자료는 첨부하지 마세요.`
- 파일 상태: `업로드됨`, `분석 완료·원본 삭제됨`, `분석 오류`
- 파일별 삭제 버튼 제공
- 업로드·삭제 중에는 같은 조작을 막고 오류를 `role="alert"`로 표시
- 사전조사 실행 중 업로드·삭제를 막는다.

조사 완료 후 `업로드 자료 반영` 요약을 보여준다. 파일명, 반영한 사실·수치의 수, 상충하거나 확인이 필요한 항목을 표시하되 원문이나 민감정보는 다시 출력하지 않는다. 조사 결과의 공개 출처와 사용자 자료 기반 근거는 서로 다른 표기로 구분한다.

## 데이터 구조

`gtm_plans`에 `market_research_documents jsonb not null default '[]'`를 추가한다. 별도 테이블과 새 저장소는 만들지 않는다.

문서 항목은 다음 최소 필드만 가진다.

```ts
type MarketResearchDocument = {
  id: string;
  fileName: string;
  mimeType: "application/pdf" | "image/png" | "image/jpeg";
  sizeBytes: number;
  sha256: string;
  status: "uploaded" | "processed" | "cleanup_pending" | "failed";
  storagePath: string | null;
  uploadedAt: string;
  processedAt: string | null;
  evidence: SanitizedDocumentEvidence | null;
  errorCode: string | null;
};
```

정제 원장은 제품·고객 사실, 가격·수량·기간이 명시된 수치, 검증 신호, 제약, 가정, 상충 근거와 근거 공백만 구조화한다. 각 항목은 문서 ID와 페이지·섹션 위치를 가지지만 원문 URL, 이메일, 전화번호, 개인명, 고객사명, 계약 상대명, 계좌·식별번호는 저장하지 않는다. 회사와 제품 이름은 사용자가 창업자 입력 폼에 이미 공개 조사 대상으로 입력한 값만 허용한다.

DB 함수가 문서 배열을 잠그고 최대 3개, 중복 ID, 상태 전이를 원자적으로 검증한다. 브라우저가 `gtm_plans` JSON을 직접 수정하지 않으며 모든 변경은 로그인·조직 소유권을 확인하는 서버 경로에서 수행한다.

## 처리 흐름

1. 업로드 API가 로그인 사용자, 조직과 진단 소유권을 확인한다.
2. 기존 열린 GTM 계획이 없으면 조사 횟수를 소비하지 않는 빈 초안 계획을 만든다.
3. 서버가 크기, MIME, 파일 확장자와 파일 시그니처를 확인하고 UUID 경로로 `evidence` 비공개 버킷에 저장한다.
4. 사전조사 버튼을 누르면 아직 처리되지 않은 파일만 대상으로 15분 만료 서명 URL을 만든다.
5. OpenAI 요청은 `store: false`, 웹·파일 검색 도구 없음, 구조화 출력만 사용한다. 문서 안의 지시문은 명령이 아니라 신뢰할 수 없는 자료로 취급한다.
6. 서버가 구조화 결과에서 이메일·전화번호·URL·긴 식별번호를 제거하고 스키마를 다시 검증한다. 안전한 정제 원장을 만들 수 없으면 공개 조사를 시작하지 않는다.
7. 정제 원장을 DB에 저장한 다음 원본 객체를 삭제한다. 삭제가 실패하면 `cleanup_pending`으로 기록하고 공개 조사를 진행하지 않으며, 다음 요청은 삭제부터 재시도한다.
8. 웹 검색이 연결된 시장동향·경쟁사·시장규모 조사에는 창업자 공개 입력만 전달한다. 정제 원장은 검색 없는 비공개 종합·시장규모 보정 단계에서만 사용하며 원본 파일, 서명 URL과 저장 경로는 전달하지 않는다.
9. 공개 조사 결과와 정제 원장을 종합하되, 공개 근거와 사용자 자료 기반 사실·가정을 구분해 표시한다.

이미 `processed` 상태인 자료는 다시 OpenAI에 원문을 보내지 않고 저장된 정제 원장을 재사용한다. 파일을 추가·삭제하면 문서 SHA-256 목록을 조사 문맥 서명에 포함해 7일 캐시를 무효화한다.

## 모델 사용

- 문서 정제: 기존 `ASSISTANT_MODEL`을 사용한다. 검색 도구 없이 중간 수준 추론과 엄격한 구조화 출력으로 실행한다.
- 시장동향·경쟁구도·TAM·SAM·SOM·교두보 시장·최종 종합: `MARKET_SIZING_MODEL`(`gpt-5.6-sol`)과 기존 웹 검색·서버 재계산 로직을 사용한다.
- 예상 가격, 구매 빈도, 초기 접근 고객 수, 3년 판매·공급 범위, 현재 검증 근거와 제약은 선택 입력이다. 비어 있어도 조사를 중단하거나 부정적 증거로 해석하지 않고 정제 자료와 공개 근거로 추정한다.

문서 정제를 별도 고가 모델이나 새 서비스로 분리하지 않는다. 기존 사전조사 3회 한도 안에서만 실행하고, 동일 SHA-256 자료는 다시 정제하지 않는다.

## 오류와 복구

- 지원하지 않는 형식·크기·위조된 MIME: 업로드 전 거부
- 저장소 기록 실패: 업로드 객체를 즉시 삭제하고 실패 반환
- 문서 누락·서명 URL 실패: 사전조사 시작 전 실패 반환
- 구조화·개인정보 제거 실패: 원문을 유지해 한 번 재시도할 수 있게 하고 `분석 오류` 표시
- 원문 삭제 실패: 정제 원장은 보존하지만 공개 조사는 중단하고 다음 요청에서 삭제부터 재시도
- 공개 조사 실패: 정제 원장은 재사용하고 기존 조사 결과가 있으면 그대로 보존
- 문서 변경 중 동시 조사: DB 상태 비교로 한 요청만 진행하고 나머지는 409 반환

조사 횟수 예약은 문서 검증과 정제 준비가 끝난 뒤 수행한다. 잘못된 파일이나 저장소 장애가 사전조사 1회를 소진하지 않도록 한다.

## 보안과 개인정보

- 원본은 Supabase 비공개 버킷과 짧은 서명 URL로만 접근한다.
- 파일 경로는 `사용자 ID/gtm-research/진단 ID/UUID`로 고정한다.
- 브라우저 입력 MIME만 신뢰하지 않고 파일 시그니처를 검증한다.
- OpenAI 원문 처리 요청에는 웹 검색, 원격 MCP, File Search, Vector Store를 연결하지 않는다.
- 공개 웹 조사 요청에는 정제 원장과 원문 파일명을 포함하지 않는다. 정제 원장은 검색 도구가 없는 비공개 종합·보정 요청에서만 사용한다.
- 원문 처리 사실, OpenAI API 처리, Borderless 저장소의 원문 자동 삭제와 정제 결과 보관을 업로드 전에 고지한다. OpenAI API의 기본 안전 모니터링 보관 가능 기간도 개인정보처리방침에서 안내한다.
- 개인정보처리방침은 무료 AI GTM 어시스턴트 첨부도 OpenAI가 처리하지만 공개 웹 검색에는 전달되지 않는다고 명시한다.

## 검증 기준

- 파일 3개·4MB·PDF/PNG/JPG 제한과 파일 시그니처 검증
- 다른 조직의 진단·계획·파일 접근 거부
- 동시 업로드에서도 최대 3개 초과 불가
- 원문 URL·경로가 웹 검색 요청에 포함되지 않음
- 이메일·전화번호·URL·긴 식별번호가 정제 원장과 웹 요청에서 제거됨
- 문서 안의 프롬프트 인젝션이 조사 지시로 실행되지 않음
- 정제 성공 후 원본 객체가 삭제되고 재조사에서 원문을 다시 전송하지 않음
- 파일 추가·삭제 시 조사 캐시가 무효화됨
- 문서 오류가 조사 횟수를 소진하지 않음
- 공개 출처와 사용자 자료 근거가 UI와 HTML 보고서에서 구분됨
- 한글·영문 UI, 키보드 조작, 320px 화면에서 정상 동작
- 관련 단위·경로 테스트, 전체 테스트, 타입 검사와 프로덕션 빌드 통과

## 배포 순서

1. DB migration 적용
2. 개인정보처리방침과 기능 코드를 `AI_GTM_RESEARCH_UPLOADS_ENABLED=false` 상태로 배포
3. 운영 환경에서 비공개 버킷·업로드·원문 삭제·웹 요청 경계를 점검
4. feature flag 활성화 후 한국어와 영어 계정으로 사전조사 smoke test

기능 플래그는 서버 환경변수를 권위값으로 사용한다. 꺼져 있으면 기존 AI GTM 어시스턴트와 사전조사는 현재와 동일하게 동작한다.
