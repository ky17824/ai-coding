# 1단계 진단 총평 설계

## 목표

준비 1단계 진단을 마친 창업자가 개별 답변의 반복 목록보다 먼저 다음 내용을 이해하도록 한다.

- 현재 글로벌 진출 준비 상태
- 아직 통과하지 못한 조건이 실제 진출에서 중요한 이유
- 지금 우선해야 할 1~3개 행동과 그 이유
- 다음 단계로 이동하기 위한 진행 순서

총평은 `gpt-5.6-sol`이 해당 진단의 전체 답변을 함께 검토해 한 번 생성한다. 같은 진단을 다시 조회할 때는 저장된 총평을 사용하고, `재진단 시작`으로 새 진단이 만들어졌을 때만 새 총평을 생성한다.

## 범위

### 포함

- 준비 1단계 완료 진단의 서술형 총평 생성
- 총평을 진단 레코드에 영속 저장
- 대시보드 상단의 기존 선결조건 박스를 총평 패널로 교체
- 기존 선결조건과 문항별 상세 내용은 하단 응답 진단 영역에 유지
- 한글·영문 총평과 UI 제공
- 생성 실패 시 진단 저장을 보존하고 제한된 재시도 제공

### 제외

- 대시보드를 열 때마다 총평 재생성
- 사용자가 총평을 직접 편집하는 기능
- 과거 총평 비교와 변화 추세 분석
- 준비 2·3단계 총평 확대. 이번 구현은 준비 1단계에 한정한다.

## 데이터 모델

`assessments`에 다음 컬럼을 추가한다.

- `stage_summary jsonb null`
- `stage_summary_locale text null`
- `stage_summary_model text null`
- `stage_summary_generated_at timestamptz null`

`stage_summary`는 자유 형식 문장 하나가 아니라 다음 고정 구조로 저장한다.

```json
{
  "headline": "현재 상태를 한 문장으로 정리한 제목",
  "overview": "전체 답변을 종합한 2~3문장 총평",
  "whyItMatters": "미충족 조건이 진출 과정에서 만드는 위험과 통과가 필요한 이유",
  "priorityActions": [
    {
      "title": "우선 행동",
      "reason": "지금 해야 하는 이유",
      "direction": "실행 방향"
    }
  ],
  "nextMilestone": "다음 단계로 가기 위해 확인할 완료 상태"
}
```

`priorityActions`는 1~3개만 허용한다. 문장 길이는 카드 안에서 읽을 수 있도록 제한한다.

## 생성 시점과 데이터 흐름

1. 사용자가 준비 1단계 진단을 제출한다.
2. 기존 방식대로 진단, 답변, 액션 아이템을 먼저 저장한다.
3. 저장된 진단 ID와 검증된 답변으로 총평 생성 함수를 한 번 호출한다.
4. `gpt-5.6-sol`의 구조화된 결과를 서버에서 검증한다.
5. 검증된 결과와 생성 언어·모델·시각을 해당 `assessments` 레코드에 저장한다.
6. 대시보드는 저장된 `stage_summary`만 읽어서 표시한다.
7. 새 재진단은 새 assessment이므로 새 총평을 생성하며, 이전 진단 총평은 변경하지 않는다.

진단과 답변 저장이 총평 생성보다 우선한다. Sol 호출이 실패해도 진단 데이터는 삭제하지 않는다.

## Sol 입력과 출력 원칙

모델에는 다음 검증된 정보만 전달한다.

- 단계명과 단계 통과 기준
- 전체 준비 1단계 질문
- 각 질문의 선택 답변, 수준, 근거 유무
- 필수 선결조건, 보완 필요, 통과, 강점 상태
- 단계 점수와 통과 기준
- 이미 서버가 계산한 액션 후보

프롬프트는 다음을 강제한다.

- 창업자가 이해할 수 있는 평이한 언어
- 답변을 나열하거나 같은 내용을 반복하지 않음
- 점수만으로 결론 내리지 않고 사업 위험과 인과관계를 설명
- 제공된 답변과 계산 결과 밖의 사실을 만들지 않음
- 불필요한 공포 표현이나 성공 가능성 단정 금지
- 가장 중요한 행동만 1~3개 선정
- 선택한 행동마다 이유와 진행 방향을 함께 제시
- 한글 진단은 한글, 영문 진단은 영문으로 작성

모델 출력은 Zod 구조화 스키마로 검증하고, 길이와 배열 개수를 서버에서 제한한다.

## UI/UX

기존 주황색 선결조건 박스의 위치와 전체 폭을 유지하되 역할을 `준비 1단계 진단 총평`으로 바꾼다.

### 데스크톱

- 왼쪽: 단계명, 총평 제목, 준비 상태 배지, 점수
- 오른쪽: 전체 총평, `왜 중요한가`, 우선 행동 1~3개, 다음 이정표
- 기존 디자인 토큰, panel 모서리, 간격, 타이포그래피를 재사용
- 경고색은 미충족 위험을 표시할 때만 사용하고, 기본 배경은 밝은 중립색으로 정돈

### 모바일

- 제목과 점수를 먼저 표시하고 본문을 한 열로 배치
- 행동 항목은 번호가 있는 짧은 목록으로 표시
- 긴 문장은 자연스럽게 줄바꿈하며 가로 스크롤을 만들지 않음

### 상태별 표시

- 총평 생성 완료: 저장된 총평 전체 표시
- 생성 중: 진단은 완료되었음을 알리고 짧은 로딩 상태 표시
- 생성 실패: 기존 계산 결과 기반의 간단한 안내와 `총평 다시 생성` 버튼 표시
- 이전 형식 진단: 자동으로 비용을 발생시키지 않고, 사용자가 원할 때 한 번 생성할 수 있는 버튼 표시

하단 문항 막대그래프와 선택 상세 패널은 유지한다. 총평의 우선 행동을 클릭했을 때 특정 문항으로 이동시키는 기능은 이번 범위에서 제외한다.

## 오류와 비용 통제

- 총평 생성 API는 인증된 사용자와 소속 조직의 assessment만 허용한다.
- 이미 `stage_summary`가 있으면 새 모델 호출 없이 저장된 값을 반환한다.
- 동일 assessment에 대한 동시 호출은 DB의 원자적 예약 상태로 한 번만 실행한다.
- 자동 재시도는 하지 않는다. 실패 시 사용자가 명시적으로 한 번 다시 요청할 수 있다.
- 모델 호출 실패는 진단, 답변, 액션 아이템 저장을 롤백하지 않는다.

## 테스트와 완료 기준

- 전체 답변이 Sol 입력에 포함되는지 확인하는 단위 테스트
- 구조화 출력 검증과 1~3개 행동 제한 테스트
- 저장된 총평이 있으면 모델을 다시 호출하지 않는 테스트
- 새 재진단은 새 총평을 생성하고 기존 총평을 보존하는 테스트
- 실패 시 진단 데이터가 유지되고 재시도 상태가 표시되는 테스트
- 대시보드에서 기존 선결조건 박스 대신 총평 패널이 표시되는 렌더 테스트
- 한글·영문 문구와 모바일 320px 이상에서 페이지 가로 넘침이 없는지 확인
- 전체 테스트, TypeScript 검사, 프로덕션 빌드, 운영 브라우저 스모크 테스트 통과

## 결정

- 생성 모델: `gpt-5.6-sol`
- 생성 횟수: assessment당 성공 결과 1회
- 표시 위치: 기존 상단 선결조건 박스
- 상세 선결조건 위치: 하단 응답 진단 영역
- 총평 성격: 현재 상태, 이유, 우선 행동, 진행 방향을 설명하는 창업자용 서술형 안내
