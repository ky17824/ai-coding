## v3.2 (2026-08-06)

'제품/서비스'의 구분 기호를 슬래시에서 가운뎃점으로 바꿨다. 문서 곳곳에서 이미 '인증·현지화·인력·법률·물류'처럼 가운뎃점으로 항목을 묶고 있어, 여기만 슬래시를 쓸 이유가 없었다. 표기만 바뀌었고 v3.1 의 내용은 그대로다.

## v3.1 (2026-08-06)

문항이 스타트업이 파는 것을 '제품'이라고만 불러서, 서비스를 파는 회사는 자기 이야기가 아닌 것처럼 읽혔다. 일반 지칭을 **'제품·서비스'**로 통일했다. 문항 구성·배점·채점 로직은 v3.0 그대로다.

바뀐 곳은 13군데다. 예: Q4 "우리 제품의 가치가" → "우리 제품·서비스의 가치가", Q19 "우리 제품이 … 어떤 품목으로 분류되는지" → "우리 제품·서비스가 … 어떻게 분류되는지". 표지의 '주요 제품 · 서비스'도 '주요 제품·서비스'로 맞췄다.

### 정해지면 좁혀 부른다

웹 진단에는 시작 화면에 **제품 / 서비스 / 아직 정하기 어려움**을 고르는 자리를 뒀다. 고르시면 그때부터 문항·보기·후속질문이 그 표현으로 바뀐다. `applyOffering()`(`lib/intake-questions.ts`)이 조사까지 함께 바꾼다 — '제품·서비스가'는 '제품이'로, '제품·서비스를'은 '제품을'로. 그래서 원문은 받침 없는 '서비스' 기준으로 조사를 적어 둔다.

고르신 표현은 저장되는 실행 액션 문구에도 반영된다. 종이 버전은 누가 쓸지 모르므로 '제품·서비스' 그대로 둔다.

**아직 안 한 것** — 고르신 값을 회사 정보로 저장하지는 않는다. 진단을 다시 여시면 '아직 정하기 어려움'으로 돌아간다. 회사마다 기억시키려면 `organizations`에 칸을 하나 늘리면 된다.

## v3.0 (2026-08-05)

문항이 짧아서 무엇을 묻는지 한 번에 와닿지 않는다는 지적을 반영했다. **55개 문항 전부**를 다시 썼다. 보기 220개와 후속질문 55개, 배점과 채점 로직은 v2.1 그대로다.

전체 대조표는 [CHANGES-v2.1-to-v3.0.md](CHANGES-v2.1-to-v3.0.md)에 있다.

### 어떻게 바꿨나

- **주어를 밝힌다** — 누구의 무엇을 묻는지 문장 안에 넣었다.
  Q12 "고객사에서 누가 쓰고 누가 결정하는지 파악하고 계신가요?" → "대표님의 고객사에서 누가 우리 서비스를 실제로 사용하고, 누가 구매를 결정하는지 파악하고 계신지요?"
- **사실 확인과 파악 여부를 나눈다** — 겪은 적이 있는지 먼저 묻고, 있었다면 원인을 아는지 잇는다.
  Q11 "관심을 보였다가 떠난 고객이 왜 떠났는지 알고 계신가요?" → "우리 제품에 관심을 보였던 고객이 이탈한 적이 있는지요? 있었다면 왜 이탈했는지 파악하고 계신가요?"
- **범위를 예시로 좁힌다** — 무엇까지 세어야 하는지 문장에서 알 수 있게 했다.
  Q5 "총 얼마가 들지" → "인증·현지화·인력·법률·물류를 모두 더해 총 얼마가 들지"
- **표준어** — '타겟'을 '타깃'으로 통일했다.

### 지키려 한 것

문항이 길어지면 읽다가 지친다. 두 문장을 넘기지 않았고, 한 문장으로 뜻이 서면 굳이 나누지 않았다.

## v2.1 (2026-08-05)

사이트 전체 문구를 다듬으면서 종이 버전과 앱이 어긋나 있던 곳을 찾아 맞췄다. 문항 구성·배점·채점 로직은 그대로다.

- **Q55** — 종이 버전과 앱의 문장이 v1.0 때부터 서로 달랐다. 더 분명한 앱 쪽 문장으로 통일했다.
  "한 고객이나 채널에 매출이 몰리는 정도를 관리하고 계신가요?" → "특정 고객이나 채널에 매출이 쏠리는 것을 어디까지 관리하고 계신가요?"
- **Q55 보기 ②** — 질문의 '쏠리다'와 어휘를 맞췄다. "몰려 있다는 것은" → "쏠려 있다는 것은"
- **섹션 이름** — "현지운영 리소스 배정" → "현지 운영 리소스 배정"

이후 두 버전이 어긋나지 않도록, 문항·보기·후속질문 전체를 docx 와 `lib/intake-questions.ts` 사이에서 대조해 불일치 0을 확인했다.

## v2.0 (2026-08-05)

문항 구성과 배점, 채점 로직은 v1.0 그대로다. **문장 표현만** 다듬었다. 문항 55개, 보기 220개, 후속질문 55개 모두 유지.

정비한 곳은 101개 문단이며, 전체 대조표는 [CHANGES-v1.0-to-v2.0.md](CHANGES-v1.0-to-v2.0.md)에 있다.

### 무엇을 고쳤나

- **겹화살괄호 → 작은따옴표** — `«고객 A»` → `'고객 A'`. 한국어 표준 인용부호로 통일.
- **보조용언 띄어쓰기** — `의존 할 지` → `의존할지`, `계속 될` → `계속 돌아갈`, `모니터링 할` → `지켜볼` 등.
- **어색한 문장** — Q44 "핵심 인력이 자리를 비워도 일이 계속 될 것이라 생각하시나요?" → "해외 진출을 이끄는 핵심 인력이 자리를 비워도 일이 계속 돌아갈까요?"
- **전제 제거** — Q1이 경영진을 3명으로 가정하던 표현("세 분이 각각")을 인원 수에 매이지 않게 바꿨다.
- **어미 통일** — `~하진 않았습니다` → `~하지는 않았습니다` (12곳).
- **의미 명확화** — Q14 "고객이 몇 곳이고 얼마나 되는지" → "고객이 될 만한 곳이 몇 곳인지", Q27 "현지 사정을 아는 사람과 우리 제품을 아는 사람이 연결돼 있나요" → "현지 사정과 우리 제품을 모두 이해하고 양쪽을 이어주는 사람이 있나요".

### 함께 반영한 곳

docx 에는 없지만 같은 문구를 쓰던 사용자 노출 텍스트도 v2.0 에 맞췄다.

- `lib/intake-questions.ts` — 문항·보기·후속질문 95곳, `action` 2곳
- `components/assessment-form.tsx` — 진행 안내와 서술형 입력 안내 3곳

## 다음 버전을 낼 때

1. `docs/survey/` 에 새 버전 docx 를 만든다. 이전 버전 파일은 지우지 않는다.
2. 대조표(`CHANGES-vX-to-vY.md`)를 남긴다.
3. `lib/intake-questions.ts` 와 `components/assessment-form.tsx` 의 문구를 같은 문장으로 맞춘다.
