## 3. 아키텍처 제안

### 3.1 지금 구조가 문구 변경을 막는 이유

`lib/ai-agent-services.ts`는 서비스 하나를 **위치 기반 튜플 한 줄**로 정의한다.

```ts
["ai-market-intelligence", 199000, "심층시장조사", "In-depth Market Research", "후보국·ICP…", "Research target…", ["market-sizing", …], ["후보국·ICP 비교", …], ["Market and ICP…", …]],
```

- 한 줄이 **700자를 넘어** 편집기에서 가로 스크롤 없이 읽을 수 없다.
- 3번째가 한국어 제목, 5번째가 한국어 설명임을 **위치로만** 알 수 있다. 문구 하나 고치려면 쉼표를 세어야 하고, 잘못 세면 한국어 설명이 영어 자리에 들어가도 타입 검사가 통과한다.
- 한국어·영어·가격·태그·결과물이 한 줄에 섞여, 문구만 바꾼 커밋도 diff에서 로직 변경과 구분되지 않는다.
- 테스트가 문구를 **문자열 그대로** 단언한다(`lib/ai-agent-services.test.ts:55`). 문구를 다듬을 때마다 관련 없는 테스트가 깨진다.

### 3.2 제안: 문구를 별도 파일로, 정의는 명명된 객체로

**변경 1 — 튜플을 객체로.** `AiAgentDefinition` 타입은 이미 있다. 튜플과 `.map()` 변환을 지우고 객체 리터럴을 직접 쓴다. 출력 형태는 동일해 다른 파일은 영향받지 않는다.

```ts
const specialists: AiAgentDefinition[] = [
  {
    id: "ai-market-intelligence",
    price: 199000,
    productKind: "specialist",
    tags: ["market-sizing", "target-market", "competition", "market-validation"],
    ...copy["ai-market-intelligence"],
  },
  …
];
```

**변경 2 — 문구를 `lib/content/ai-services-copy.ts`로 분리.** 서비스 id를 키로 한 사전 하나만 둔다.

```ts
export const aiServiceCopy = {
  "ai-market-intelligence": {
    title: { ko: "심층 시장조사", en: "In-depth Market Research" },
    description: { ko: "어느 나라의 …", en: "Research target markets, …" },
    deliverables: { ko: ["후보 국가와 목표 고객 비교", …], en: […] },
  },
  …
} satisfies Record<string, ServiceCopy>;
```

효과: 문구 수정이 **이 파일 한 곳**에서 끝나고, 가격·태그·문항 매핑 로직과 diff가 분리된다. 비개발자도 이 파일만 보고 검토할 수 있다.

**변경 3 — 테스트가 문자열을 복제하지 않게.** 문구를 단언하는 테스트는 사전에서 import해 비교한다.

```ts
expect(ko?.title).toBe(aiServiceCopy["ai-market-intelligence"].title.ko);
```

단, `GPT-5.6 Sol`이 노출되지 않아야 한다는 **금지 단언은 그대로 둔다.** 이건 문구가 아니라 정책이다.

### 3.3 하지 않을 것

| 후보 | 판단 |
|---|---|
| 문구를 DB(`service_offerings`)로 이전 | **안 한다.** 문구는 배포 주기로 충분하고, DB로 옮기면 로컬·프리뷰·운영 문구가 갈라진다 |
| i18n 라이브러리(next-intl 등) 도입 | **안 한다.** 언어가 2개, `{ko, en}` 객체로 충분하다 |
| 헤드리스 CMS 연동 | **안 한다.** 편집자가 아직 없다 |
| 문구용 JSON/YAML 파일 | **안 한다.** 타입 검사를 잃는다. TS 객체가 더 안전하고 도구도 필요 없다 |

### 3.4 이관 순서

1. `lib/content/ai-services-copy.ts`를 만들고 1장의 확정 문구를 넣는다.
2. `lib/ai-agent-services.ts`의 튜플을 객체로 바꾸고 문구 자리에 사전을 참조시킨다.
3. `npx tsc --noEmit`과 `npm test`로 출력이 같은지 확인한다.
4. 문자열을 복제하던 테스트를 사전 참조로 바꾼다.

각 단계가 독립 커밋이다. 1~2단계에서 화면 출력은 문구 변경분 외에 달라지지 않아야 한다.

### 4.2 제안

**제안 1 — 전문가와 패키지를 두 섹션으로 나눈다** (문제 A)

```
필요한 것만 고르기          ← specialist 7개
  [7개 카드]
묶어서 진행하기             ← package 4개
  [4개 카드]
```
`productKind`로 이미 구분되어 있어 `filter` 두 번이면 된다. 섹션 소제목은
**`필요한 항목만 고르기`**, **`여러 항목을 묶어서 진행하기`**.

**제안 2 — 반복되는 제공자 줄을 결과물로 교체** (문제 B, C)

카드에서 `avatar + providerName + providerTitle` 블록을 빼고 그 자리에 결과물 상위 2개를 체크 표시로 넣는다. 제공자 정보는 페이지 상단 안내 배너에 한 번만 두면 충분하다.

```
심층 시장조사
어느 나라의 어떤 고객을 먼저 공략할지…
  ✓ 후보 국가와 목표 고객 비교
  ✓ 시장규모 추정 (TAM·SAM·SOM·교두보)
199,000원 (부가세 별도) · 결제 후 즉시 시작
```
새 데이터는 필요 없다. 카드 높이도 지금(390px)을 유지할 수 있다.

**제안 3 — 패키지 카드에 포함 전문가를 표시** (문제 A)

`includedAgentIds`가 이미 있으므로 `이 패키지에 포함: 심층 시장조사 · 고객 검증`처럼 이름을 나열한다. 지금은 패키지를 사도 무엇이 들어오는지 목록에서 알 수 없다.

> **선결 과제 — 가격 검토 필요.** 낱개 합계와 비교하면 4개 중 2개가 더 비싸다.
>
> | 패키지 | 가격 | 낱개 합계 | 차이 |
> |---|---|---|---|
> | 시장 가능성 | 349,000 | 328,000 | **+21,000 (더 비쌈)** |
> | 현지화·진입 | 649,000 | 697,000 | −48,000 |
> | 실행계획 | 349,000 | 298,000 | **+51,000 (더 비쌈)** |
> | 종합 진출 설계 | 1,190,000 | 1,323,000 | −133,000 |
>
> 포함 내역을 노출하면 고객이 직접 더해 볼 수 있다. **가격을 먼저 조정하거나**,
> 조정 전이라면 `절감액` 문구는 넣지 않는다. 이건 문구 문제가 아니라 가격 정책 결정이다.

**제안 4 — 준비도 영역 필터를 되살린다** (문제 D)

`tags` 데이터를 그대로 쓰되, 태그 원문이 아니라 준비도 영역 이름으로 묶는다.

`전체` / `시장·경쟁` / `고객 검증` / `현지화` / `규제` / `파트너` / `자금` / `실행`

기존 `.filter-row` 스타일을 재사용하고, 선택 시 `?tag=`를 갱신한다. 서버 필터링 로직(`page.tsx` L17)은 이미 있다.

**제안 5 — 로그인 사용자에게 진단 기반 추천 띠** (문제 E)

목록 상단에 `내 진단에서 부족한 항목에 맞는 서비스`를 3개까지 보여준다.
`matchAiAgentServices(tag, locale)`가 이미 있어 진단의 우선 액션 태그를 넘기면 된다.
비로그인 상태에서는 이 영역을 숨기고 `준비도 진단 먼저 하기` 버튼을 둔다.
제목이 약속한 흐름(진단 → 부족한 부분 → 서비스)을 화면에서 완성하는 항목이다.

**제안 6 — 반응형 그리드를 한 줄로 정리** (문제 F)

```css
.service-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: 20px;
}
```
`@media (max-width: 900px)`의 `.service-grid` 규칙을 **삭제**한다. 태블릿 2열이 자동으로 생기고 CSS는 오히려 줄어든다.

**제안 7 — 카드에 `부가세 별도` 표기** (문제 G)

`service-card.tsx`의 가격 아래 `결제 후 즉시 시작` 옆이나 아래에 `부가세 별도`를 넣는다.
`getAiPriceWithVat`를 목록에서도 호출해 총액을 보여주는 방법도 있으나, 표기 한 줄이 더 간단하고 상세 화면과 어긋나지 않는다.

### 4.3 이번에 하지 않을 것

비교표 화면, 장바구니, 다중 선택 결제, 카드 애니메이션, 스켈레톤 로딩은 제안하지 않는다.
지금 문제는 정보 구조이지 상호작용이 아니다.

## 7. 검증 기준

- `/services` 한국어 화면에 가운뎃점 4개 이상 연속인 문장이 없다.
- 한글과 영어가 한 어절에 섞인 표기가 없다.
- 서비스 설명 11개의 서술어가 모두 같은 단어로 끝나지 않는다.
- 카드에서 상세로 들어가지 않고도 각 서비스의 결과물을 2개 이상 확인할 수 있다.
- 768px과 1280px에서 각각 2열, 3열로 표시된다.
- 목록의 가격 표기와 결제 화면의 청구 금액이 어긋나지 않는다(부가세 표기 존재).
- 영문 화면, 가격 값, 태그, 서비스 id는 변경되지 않았다.
- `npx tsc --noEmit`과 `npm test`가 통과한다.
