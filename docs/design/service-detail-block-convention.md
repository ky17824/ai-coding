# 서비스 상세 블록 서식 규칙

적용 대상: `app/services/[id]/page.tsx`의 `detail-block`
상태: **표준** — 새 블록을 추가하거나 기존 블록을 고칠 때 이 규칙을 따른다.

## 규칙

**제목 아래 본문은 항상 목록이다. 맨문단(`<p>`)을 두지 않는다.**

| 블록 | 목록 형식 | 이유 |
|---|---|---|
| 결과물 | `<ul>` 불릿 | 순서가 없는 산출물 나열 |
| 진행 방식 | `<ol>` 번호 | **순서가 의미를 가진다.** 1→2→3으로 진행된다 |
| 필요정보 | `<ul>` 불릿 | 순서가 없는 준비물 나열 |
| 이 서비스의 한계 | `<ul>` 불릿 | 순서가 없는 제외 항목 나열 |
| 취소·환불 정책 | `<ul>` 불릿 | 조건 나열. 한 문단에 두 문장을 붙이지 않는다 |

**번호 목록은 진행 방식 하나뿐이다.** 나머지는 전부 불릿이다.

## 제목 규칙

짧은 명사구로 쓴다. 서술절을 제목으로 쓰지 않는다.

- ✅ `결과물` · `진행 방식` · `필요정보` · `이 서비스의 한계` · `취소·환불 정책`
- ❌ `이 보고서가 결론 내리지 않는 것` — 옆 제목들과 리듬이 어긋난다
- ❌ `이 보고서의 한계` — 2차의 전문가 수행 상품은 보고서가 아니다. `서비스`가 17종 전부에 맞는다

## 문장 규칙

- 한 항목에 한 문장. 두 문장을 이어 붙이면 나눈다.
- 항목이 길어지면 `대상 — 설명` 형태로 쓴다.
  예) `인터뷰와 시범판매의 실제 수행 — 설계까지 제공하며 실행은 직접 하셔야 합니다.`
- 설명 문단을 목록 위에 얹지 않는다. 그 내용이 필요하면 **첫 항목**으로 넣는다.
  예) `전문가 검토는 포함되지 않습니다.`

## 강조 규칙

**어느 블록에도 배경·테두리를 주지 않는다. 다섯 블록은 전부 같은 모양이다.**

한때 `이 서비스의 한계`를 옅은 배경 박스로 감싼 적이 있다. 제외 항목이 결과물과
같은 무게로 읽히는 것을 막으려는 의도였지만, 실제 화면에서는 박스가 블록의 흐름을
끊어 그 자리만 눈에 걸렸다. 되돌렸다.

성격 구분은 **제목과 순서**가 한다. `이 서비스의 한계`는 `필요정보` 다음,
`취소·환불 정책` 앞에 온다 — 구매 결정에 필요한 순서 그대로다.
제목이 명확하면 배경이 필요 없다.

문구가 오해를 살 때의 해법도 배경이 아니라 문구다. 이 블록의 이전 제목이
`전문가 검증`이던 시절 판매하지 않는 전문가 검토를 약속하는 것으로 읽혔는데,
이는 제목을 `이 서비스의 한계`로 바꾸고 첫 항목에 `전문가 검토는 포함되지 않습니다.`를
두어 해결했다. 배경으로 덮을 문제가 아니었다.

## 문구의 출처

블록 본문은 화면에 직접 쓰지 않고 `lib/catalog`에서 온다.

| 블록 | 출처 |
|---|---|
| 결과물 | `copy.ts` `PRODUCT_COPY[id].deliverables` |
| 진행 방식 1단계 | `copy.ts` `TIER_FIRST_STEP[tier]` — 계층마다 다르다 |
| 필요정보 | `copy.ts` `SHARED_REQUIRED_INPUT` + `PRODUCT_REQUIRED_INPUT[id]` 또는 `REQUIRED_INPUT_BY_AGENT` |
| 이 서비스의 한계 | `copy.ts` `TIER_DISCLOSURE[tier]`(A·B만) + `PRODUCT_BOUNDARY[id]` 또는 `HUMAN_BOUNDARY` |
| 취소·환불 정책 | `copy.ts` `REFUND_POLICY` |

**상품별로 다른 값을 화면에서 분기하지 않는다.** 화면은 배열을 받아 그리기만 한다.

## 검증

`lib/catalog/catalog.test.ts`가 아래를 강제한다.

- 17종 전부(게이트로 가려진 2차 8종 포함) ko·en 양쪽에서 모든 블록이 비어 있지 않다
- A·B의 한계 첫 항목은 `전문가 검토는 포함되지 않습니다.`
- C·D·M은 자기가 파는 검토를 스스로 한계로 내걸지 않는다
- 필요정보는 상품마다 다르다

`app/services/[id]/page.test.ts`가 서식을 강제한다.

- 블록 본문에 맨문단(`<p>`)이 남아 있으면 실패한다
- 번호 목록이 `진행 방식` 말고 더 생기면 실패한다
- 어느 블록에도 `detail-block--boundary` 같은 별도 스타일이 붙으면 실패한다
- 옛 제목(`전문가 검증`·`결론 내리지 않는 것`)이 되살아나면 실패한다

## 2차 개편 시 확인할 것

- **취소·환불 정책이 전문가 상품에 맞지 않는다.** 현재 문구는 "보고서 생성 시작 전"
  기준이라, 전문가가 배정된 뒤 취소하는 경우의 인건비 처리 규칙이 없다.
  `REFUND_POLICY`를 계층별로 나눠야 한다.
- `localizeCatalogProduct`가 모든 카탈로그 상품에 `type: "ai_agent"`를 준다.
  전문가 상품은 제공자·일정 표시가 달라야 하므로 함께 손본다.
