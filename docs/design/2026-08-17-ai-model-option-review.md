# 검토: `ai-model-option.md` (AI 전문가 서비스 모델 교체·폴백·관리자 설정)

검토일 2026-08-17 · 대상 `readiness-v5-worktree/ai-model-option.md` (531줄)
검토 기준: 이 저장소의 현재 코드(2026-08-17 main), 이번 주 실측한 OpenAI/Anthropic API 동작, 공식 문서

**총평.** 방향은 옳고 범위 절제가 좋다(옵션 B 채택, 범용 오케스트레이터 배제, 단가 UI 편집
금지, 설정 버전화). 그러나 **구현하면 바로 깨지는 사실 오류 3개**와, **설계 의도가
문서와 어긋난 지점 1개**가 있다. 아래 순서는 중요도 순이다.

---

## A. 반드시 고쳐야 하는 것

### A1. 문서와 요구가 다르다 — Opus는 "폴백"인가 "기본"인가

요구: "기본적으로 gpt-5.6-luna를 사용하고 **보고서는 Claude Opus 5**를 사용하는 구조."
문서 §1: 최종 보고서도 **Luna가 기본**, Opus는 Luna가 실패했을 때 **1회 폴백**.

둘은 다른 제품이다. 폴백 구조에서 Opus는 거의 호출되지 않고, 보고서 품질은 Luna가
결정한다. 요구대로라면 `final_report.primary = anthropic:claude-opus-5`여야 한다.

다행히 문서의 설계(§8.1 `routes` JSON)는 두 경우를 모두 담을 수 있으므로 **아키텍처는
바꿀 필요가 없다.** 바꿔야 하는 것은 §1의 "권장 기본값" 표와 §11 6단계의 초기 설정,
그리고 아래 A2의 우선순위다.

**권장 기본값**

| 단계 | 기본 | 폴백 |
|---|---|---|
| 입력 분류 | Luna (effort low) | 없음 |
| 공개 조사 | Luna (effort medium) + web_search | 없음 |
| 최종 보고서 | **Opus 5** (effort medium, 패키지 high) | **Luna 1회** |

역방향 폴백(Opus 실패 → Luna)이 자연스럽다. Luna는 이미 앞 단계에서 살아 있음이
확인된 공급자이고 비용이 낮다.

원가 영향(보고서 단계, 출력 8~16k 토큰): Opus $0.20~0.40 vs Luna $0.01~0.02.
50,000원 상품 변동비의 1% 안쪽이다. 결정 근거는 비용이 아니라 품질이어야 한다.

### A2. "두 공급자 출력을 기존 `aiAgentReportSchema`로 통일"은 그대로는 400이다

문서 §11 2단계는 Zod 스키마를 그대로 Anthropic에 보내는 것을 전제한다.
**Anthropic 구조화 출력은 `minLength`/`maxLength`/`pattern`/`maxItems`를 지원하지 않고,
무시가 아니라 400으로 거절한다** (공식 문서 확인, 2026-08-17).

현재 `lib/ai-agent-report.ts`는 `reportText = z.string().trim().min(1).max(6000)`을 비롯해
`.max(` 36곳을 쓴다. 그대로 보내면 Opus 호출은 전부 실패한다.

A1을 반영하면 이건 "폴백 경로의 예외 처리"가 아니라 **주 경로**다. 문서에 없는 작업이
하나 추가된다.

- `lib/ai-models/schema.ts` — Zod → JSON Schema 변환 시 미지원 키워드를 제거
  (`toModelSchema`). 응답 검증은 원래 Zod로 한다. 길이 초과는 이미 있는
  `parseTruncatingStrings`(`lib/lenient-text-format.ts`)가 자른다.
- 테스트: 변환 결과를 순회해 미지원 키워드 0개 단언.

같은 이유로 OpenAI 쪽도 `format: "uri"`를 거절한다는 것을 이번 주에 겪었다
(`lib/model-schema-formats.test.ts`). **모델에 보내는 스키마와 검증 스키마는 분리한다**는
원칙을 문서 §4에 명시하는 것이 좋다.

### A3. 마이그레이션 번호 `017`은 이미 쓰였다

문서 §13: `supabase/migrations/017_ai_model_routing.sql`.
현재 적용된 마지막 번호는 **021**이다(017 태그 백필, 018 관리자 사용자 관리, 019 베타 접근,
020 실패 처리 수정, 021 진행 단계). `supabase db push`는 번호가 낮으면 **조용히 건너뛴다.**
다음은 022다.

같은 절 "현재 관리자 사용자 관리 작업과 파일 충돌을 피하고"도 낡았다 — 018로 이미 main에
합쳐졌다. `/admin/users`와 `components/admin-nav.tsx`, `.admin-subnav`는 존재하며 그대로
재사용하면 된다.

## B. 설계 결함 — 고치지 않으면 운영에서 드러난다

### B1. 300초 예산 안에서의 폴백

문서 §5는 폴백 조건을 오류 종류로만 정한다. **시간**이 빠져 있다.

현재 라우트는 `maxDuration = 300`, 데드라인 285초다. 실측(주문 6d76942a): 분류+조사에
약 90초, 보고서 작성이 가장 길다. 보고서 1차 시도가 150초 걸리고 실패했다면 남는 예산은
40초 남짓이고, 폴백 호출은 시작하자마자 Vercel에 잘린다. 잘리면 catch가 돌지 않아 실행이
`generating`에 묶인다 — 이번 주에 정확히 이 형태를 겪었다.

**추가할 규칙**: 폴백은 `remaining ≥ FALLBACK_MIN_MS`(제안 120초)일 때만 시도한다.
부족하면 폴백 없이 실패 RPC를 부르고 `error_message`에 "budget_exhausted_no_fallback"을
남긴다. §12.2 통합 테스트에 이 케이스를 넣는다.

### B2. "공급자 SDK 기본 재시도 뒤에 폴백"은 현재 코드 결정과 충돌한다

문서 §5.1: "공급자 SDK의 기본 재시도 뒤에도 실패했을 때만 폴백한다."
현재 라우트는 **`maxRetries: 0`**을 명시한다. SDK 기본 재시도 2회가 지수 백오프와 함께
300초 예산을 넘겨 실행을 묶었기 때문이다(GTM 어시스턴트 research 라우트에서 겪고 고침).

권장: 두 공급자 모두 `maxRetries: 0` 유지. 재시도 역할은 폴백 1회가 대신한다.
문서에서 이 문장을 바꿔야 한다.

### B3. 완료·실패 RPC 시그니처 변경은 오버로드를 만든다

§8.2 "완료·실패 RPC가 … 모델 시도 기록을 원자적으로 저장하도록 확장한다."
PostgreSQL에서 `create or replace function`에 **인자를 추가하면 새 오버로드가 생기고 옛 함수는
남는다.** 라우트가 어느 쪽을 부르는지는 인자 개수로 결정되므로 조용히 옛 것을 계속 부를 수
있다. 020 마이그레이션 테스트가 이 이유로 시그니처 일치를 단언한다.

권장: 022에서 옛 시그니처를 **명시적으로 `drop function`** 한 뒤 새 시그니처를 만들고,
`revoke`/`grant`를 다시 건다. 테스트에 "옛 시그니처가 `pg_proc`에 남아 있지 않다"를 넣는다.

### B4. `effort`는 Anthropic에서 명시하지 않으면 `high`다

§4.1 `StageRoute.effort`는 선택(`?`)이다. Anthropic Messages API는 Opus 5에서 `effort`
기본값이 **`high`**다(공식 문서). 관리자가 비워 두면 의도치 않게 가장 비싸고 느린 설정으로
돈다. 어댑터가 **항상** effort를 보내도록 하고, 허용 목록에서 모델별 지원 값
(Luna: none/low/medium/high/xhigh/max · Opus 5: low/medium/high)을 두어 UI 드롭다운이
그 값만 보이게 한다 — 문서 §9.4 "해당 모델이 지원하는 값만 표시"와 일치시키면 된다.

### B5. 사용자에게 어느 모델이 썼는지 알려야 한다

§5.3은 사용자가 공급자 오류를 보지 않게 하는 데만 신경 쓴다. 반대 방향이 빠져 있다.
보고서 화면 상단은 지금 "프론티어 모델"이라고만 쓴다. 폴백이 일어나면 같은 상품을 산
두 사용자가 다른 모델의 보고서를 받는다. 이 저장소의 진행표시 정직성 원칙
(`docs/design/progress-indicator-honesty.md`)과 같은 줄기에서, **보고서 메타에
"작성 모델: Claude Opus 5"를 표시**하는 것을 권한다. `ai_agent_runs.model`에 이미 값이
있으므로 화면 한 줄이다.

## D. 있으면 좋은 것 (범위 안에서 작음)

1. **모델 허용 목록에 `deprecated_at`** — 공급자가 모델을 폐기하면 UI에서 선택 불가로 바꾸되,
   이미 저장된 설정 버전은 그대로 읽힌다. 실행 시점에 폐기 모델이면 즉시 실패가 아니라
   목록의 `replacement`로 자동 치환하고 로그를 남긴다.
2. **관리자 페이지 상단에 "최근 24시간 실행 수·폴백 발생 수"** — §14 지표 중 두 개만 먼저.
   `ai_agent_runs.model_attempts`를 세는 쿼리 하나면 된다. 설정 화면에서 결과를 못 보면
   설정을 바꿀 근거가 없다.
3. **설정 저장 시 "현재 실행 중인 건수" 표시** — "새 실행부터 적용"이 실감나게.
4. **`routes` JSON 스키마를 Zod로 두고 저장·읽기 양쪽에서 검증** — 손으로 DB를 고친
   경우도 잡힌다.

## E. 그대로 두어도 좋은 결정 (동의)

- 옵션 B 채택, C 배제 — 두 공급자·세 단계에 프레임워크는 과하다
- 관리자가 임의 모델 문자열을 입력하지 못하게 한 것
- 단가·API 키를 UI에서 편집하지 않는 것
- 설정을 덮어쓰지 않고 버전으로 쌓고, 롤백도 새 버전으로 기록하는 것
- 실행 예약 시 설정을 스냅샷으로 고정하는 것
- 폴백이 출처·의미·상태 검증을 우회하지 않는다는 원칙
- 별도 기능 플래그 없이 "이전 설정으로 되돌리기"를 롤백 수단으로 삼는 것
- 시도 기록을 별도 테이블이 아니라 `model_attempts` jsonb로 두는 것

## F. 수정 후 문서가 가져야 할 모양 (요약)

1. §1 표를 A1대로 바꾸고, "왜 Opus가 보고서 기본인가"를 한 줄로 적는다(품질 판단이며
   원가 영향은 1% 미만).
2. §4.2 파일 경계에 `lib/ai-models/schema.ts`(A2)를 추가한다.
3. §5.1에 시간 예산 조건(B1)을 넣고 "SDK 재시도" 문장을 `maxRetries: 0`으로 바꾼다(B2).
4. §8.2에 RPC 시그니처 교체 절차(B3)를 적는다.
5. §9.4에 effort 필수·모델별 허용값(B4)을 적는다.
6. §5.3 또는 새 절에 사용자 노출(B5)을 적는다.
7. §7 표에 Opus 캐시 단가와 토크나이저 주석(C)을 넣는다.
8. §13 번호를 022로, `DESIGN.md`를 `docs/design/ai-model-routing.md`로 바꾼다.

이 여덟 가지를 반영하면 문서는 그대로 구현 사양으로 쓸 수 있다.
