# 생성 파이프라인 로드맵 — 무엇을 언제 결정하는가

작성 2026-08-17 · 대상: AI 전문가 보고서 생성 경로

## 왜 이 문서가 있는가

보고서 생성이 Vercel 함수 하나(300초) 안에서 돌고, 실측 293초로 데드라인 285초를 8초 넘겨
완성된 Opus 보고서가 폐기됐다. 해법이 여럿이고 비용과 시점이 달라, **무엇을 언제 결정하는지**를
남긴다. 판단 기준은 고객 수가 아니라 **상품 구성과 결제 여부**다.

## 실측 (주문 bf45d83b, 심층 시장조사, 2026-08-17)

| 구간 | 소요 | 비고 |
|---|---|---|
| 입력 정리 (Luna medium) | 2초 | 무시 가능 |
| 공개 자료 조사 (Luna low) | 52초 | 웹검색 8회 |
| 출처 검증 | 0초 | 로컬 |
| **보고서 (Opus 5 medium)** | **239초** | **본문 + 시장규모 2호출** |
| 합계 | **293초** | 데드라인 285초 초과 → `budget_exhausted` |

**보고서가 전체의 82%를 쓴다.** 다른 구간을 줄여도 여기를 못 건드리면 의미가 없다.

## 네 가지 방법

| | 내용 | 실제 소요 | 효과 |
|---|---|---|---|
| **1** | 시장규모 호출을 본문과 병렬화 | 코드 10~15분 + 실측 10분 | 239초 → 160~180초 추정 |
| **2** | 조사 결과를 저장해 재시도·정정에서 재사용 | 30~40분 | 정정 재생성 52초 절약 |
| **3** | 단계별 요청 분리 (근본 해결) | 2~4시간 | 총 시간 제한 소멸 |
| **4** | `after()`로 응답 후 처리 | — | **해당 없음** — 같은 함수 수명 안이라 300초를 못 벗어난다 |

소요는 **벽시계 기준**이다. 코딩은 에이전트가 하므로 사람 공수 개념이 아니다.
실제로 시간이 드는 곳은 모델 호출 대기(1회 60~240초), 프로덕션 실행 확인(사람이 눌러야 함),
죽은 실행의 15분 리스 만료다.

## 결정 시점

### Vercel Pro — 첫 유료 결제 직전

아키텍처 결정이 아니라 **운영 여유**다. 월 $20 수준, 되돌리기 쉬움. 함수 상한 300초 → 800초.

- **지금은 불필요하다.** 관리자 2명이 베타로 돌리므로 실패해도 아무도 다치지 않는다.
- **결제를 받는 순간 성격이 바뀐다.** 5만원을 낸 사람의 보고서가 8초 차이로 폐기되면
  환불과 신뢰 문제다.
- Pro는 **개발 속도 자체를 산다.** 293초를 285초에 맞추려 검색 횟수와 effort를 깎는 고민이
  사라지고 품질에만 집중할 수 있다.
- **다만 Pro는 옵션 3의 대체재가 아니다.** 800초로 올려도 HTTP 연결을 5분씩 붙드는 취약함은
  그대로이고, 브라우저를 닫으면 실행이 뜬다.

### 옵션 3 (단계 분리) — 세 방아쇠 중 하나라도 당겨지면

1. **패키지 상품을 열 때 (가장 먼저 올 방아쇠).**
   패키지는 조사·보고서가 `high`로 승격되고(`route.ts:336`) 에이전트가 7개다.
   스페셜리스트 하나가 293초인데 패키지는 800초도 위험하다.
   **고객 수와 무관하게 상품 구성이 결정한다.**
   현재 패키지 2종: 진출 가능성 진단 119,000원 · 진입 설계 249,000원.
   **이 둘을 여는 날이 곧 옵션 3의 마감일이다.**

2. **"탭 닫아도 계속됩니다"를 지켜야 할 때.**
   생성 화면에 이미 그렇게 적혀 있으나 지금은 사실이 아니다. HTTP 연결이 끊기면 실행이 뜬다.
   **고객 1명부터 문제다.**

3. **동시 실행이 겹치기 시작할 때.**
   5분짜리 요청이 여러 개 동시에 붙들리면 함수 동시성과 비용이 같이 뛴다.
   체감 시작은 대략 **하루 10~20건**.

### 왜 지금 옵션 3을 해도 되는가

고객이 없어 실패 비용이 0이다. 나중에 하면 **운영 중인 파이프라인**을 바꾸게 된다.
리스·정정한도 멱등성은 트래픽이 있을 때 손대면 훨씬 위험하다.

## 권하는 순서

```
방법 1 (병렬화)
  → Opus 보고서 프로덕션 완주·품질 확인      ← 여기서 모델 선택이 확정된다
  → (만족하면) 옵션 3
  → 패키지 출시
  → 유료 오픈 직전 Vercel Pro
```

**품질 확인을 구조 작업 앞에 두는 이유**: 지금 Opus가 좋다는 근거는 오프라인 1건이고,
프로덕션에서 완주한 Opus 보고서는 아직 없다. 품질이 기대에 못 미치면 모델 선택이 바뀌고
시간 예산도 달라지므로, 구조를 먼저 바꾸면 헛일이 될 수 있다.

이 순서면 Pro 결제를 가장 뒤로 미룰 수 있고, 구조 작업은 고객이 없을 때 끝난다.

## 호스팅 대안 검토 (결론: 지금 옮기지 않는다)

이 저장소는 Vercel 결합이 거의 없다 — `@vercel/*` 패키지 없음, `waitUntil` 없음,
`vercel.json`은 리전 한 줄. 즉 **나중에 옮길 수 있다**는 뜻이지 지금 옮겨야 한다는 뜻이 아니다.

- **상주 서버(Railway·Render·Fly.io·VPS)**: 요청 시간 제한이 아예 없다. `next start` 그대로.
  잃는 것은 프리뷰 배포, 글로벌 CDN, 무중단 롤백.
- **AWS Lambda(OpenNext/SST)**: 900초. 제어는 크지만 운영 부담도 크다.
- **Cloudflare Workers**: CPU 시간 기준이라 모델 대기가 거의 공짜. 다만 Next.js 15 App Router
  지원이 OpenNext 경유라 덜 성숙하고, 지금 잘 도는 것을 흔드는 위험이 있다.

**호스팅 교체는 지금 문제를 푸는 가장 비싼 방법이다.** 300초는 Vercel의 한계가 아니라
서버리스의 한계이며, 옵션 3을 하면 어느 호스팅이든 상관없어진다.
