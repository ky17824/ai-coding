# 진행 표시 원칙 — 서버가 아는 것만 그린다

작성 2026-08-17 · 적용 대상: 오래 걸리는 작업의 대기 화면 전부

## 원칙

**진행 표시는 서버가 실제로 기록한 상태에서만 나온다. 시간에 맞춰 저 혼자 넘어가는
진행 표시는 만들지 않는다.**

시간 기반 애니메이션은 만들기 쉽고 보기에도 좋다. 문제는 그것이 거짓말이라는 점이다.
작업이 30초 만에 죽어도 화면은 계속 4분짜리 연출을 이어간다. 사용자는 기다릴 이유가
없는데 기다리고, 정작 손을 써야 할 때(작업 이어가기) 그 사실을 모른다.

이 원칙은 이 제품에서 이미 두 번 같은 이유로 내린 결정과 같은 줄기에 있다.

- 1차 론칭에서 팔지 않는 '전문가 검증' 블록을 상품 상세에서 걷어낸 것
- 대시보드에서 서로 다른 척도의 점수를 나란히 두지 않기로 한 것

셋 다 "화면이 사실보다 더 많이 말하지 않는다"는 같은 규칙이다.

## 따라오는 규칙

1. **단계는 실제 경계에서만 기록한다.** 모델 호출 하나, 검증 하나가 한 단계다.
   보기 좋으라고 단계를 쪼개지 않는다. 쪼갠 만큼 서버가 그 시점을 실제로 기록해야 한다.
2. **단계 안의 진척도는 그리지 않는다.** 서버가 "조사 중"까지만 알고 "조사 60%"는
   모른다면 60%를 그릴 수 없다. 진행 막대 대신 현재 단계 표시 하나만 움직인다.
   움직이는 것은 "이 단계가 진행 중"이라는 사실만 뜻한다.
3. **멈추면 멈춘 채로 둔다.** 단계가 넘어가지 않으면 화면도 넘어가지 않는다.
   그것이 사용자가 복구 조치를 취해야 할 때를 아는 유일한 단서다.
4. **경과 시간은 실제 시작 시각에서 계산한다.** 화면을 연 시각이 아니다.
   다시 들어와도 같은 값이 나와야 한다.
5. **기록 실패가 작업을 막지 않는다.** 진행 표시는 부가 정보다. 단계 기록에
   실패하면 로그만 남기고 작업은 계속한다.
6. **복구 버튼은 실제로 복구할 수 있을 때만 보인다.** 서버가 거절할 조작을
   눌리는 상태로 두지 않는다. 눌러도 아무 일이 없는 버튼은 고장으로 읽힌다.

## 현재 구현

| 자리 | 파일 |
|---|---|
| 단계 컬럼과 기록 함수 | `supabase/migrations/021_ai_agent_generation_stage.sql` |
| 단계 기록 지점 | `app/api/ai-agent-runs/[orderId]/route.ts` (`markStage`) |
| 플로우차트 | `components/ai-generation-flow.tsx` |
| 폴링·복구 버튼 노출 | `components/ai-agent-workspace.tsx` |
| 스타일 | `app/globals.css` (`.ai-flow`) |

AI 전문가 보고서 생성의 단계는 다섯이다.

`context`(입력 정리) → `research`(공개 자료 조사) → `verify`(출처 검증)
→ `report`(보고서 작성) → `finalize`(최종 점검·저장)

단계 목록은 마이그레이션의 check 제약과 `GENERATION_STAGES` 두 곳에 있고,
어긋나면 `components/ai-generation-flow.test.tsx`가 실패한다.

## 표시 규칙

- 완료·진행·대기 세 상태를 **색과 모양 둘 다로** 구분한다. 완료는 체크 표시,
  진행은 가운데 점, 대기는 빈 원. 색만으로 구분하면 안 된다.
- `prefers-reduced-motion`이 켜져 있으면 맥동을 끄고 고정된 점을 보여 준다.
- 진행 중인 항목에 `aria-current="step"`을 준다.
