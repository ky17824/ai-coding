# 준비도 차트 인코딩 규칙

적용 대상: `components/answer-question-chart.tsx`, `app/globals.css`의 `.answer-question-*`
상태: **표준** — 차트에 정보를 하나 더 얹고 싶을 때 이 문서를 먼저 읽는다.

## 원칙

**하나의 시각 채널은 하나의 변수만 나타낸다.**

이 차트는 문항마다 서로 다른 두 가지를 말해야 한다.

1. **얼마나 답했나** — 응답 수준 1~4
2. **무엇이 막고 있나** — 게이트 상태(필수 선결 조건 · 90일 검증)

두 정보는 서로 독립이다. 응답 수준이 3이어도 필수 문항이면 게이트를 막고,
수준이 2여도 90일 검증으로 이월했으면 지금은 막지 않는다. 그러므로 채널도 나눈다.

| 채널 | 담는 정보 |
|---|---|
| **막대 높이** | 응답 수준 1~4 (25% · 50% · 75% · 100%) |
| **막대 명도** | 응답 수준 1~4 (연함 → 진함) |
| **막대 테두리** | 게이트 상태. 실선 = 필수 선결 조건, 파선 = 90일 검증 |

## 명도는 수준만 나타낸다

`--chart-level-1` → `--chart-level-4`가 **반드시 연함에서 진함 순서**여야 한다.

명도는 보는 사람에게 "많다 · 좋다"로 읽힌다. 이 순서가 깨지면 차트가 사실과
반대되는 인상을 준다.

> **실제로 있었던 문제.** 예전에는 명도가 수준이 아니라 상태를 나타냈다.
> `필수 선결 조건`이 가장 진한 `#0e3b2b`를, `90일 검증`이 중간 명도를 썼는데
> 둘 다 응답 수준이 1~2인 **낮은 문항**이었다. 그 결과 화면에서 가장 새까만 막대가
> 가장 못한 문항이 되어, "진할수록 좋다"는 직관과 정반대로 읽혔다.
> 게이트 상태를 테두리로 옮겨 해결했다.

## 게이트 상태는 배경을 칠하지 않는다

필수 선결 조건과 90일 검증은 **테두리로만** 표시한다. 배경이나 패턴을 쓰면
명도 순서를 다시 깨뜨린다.

예전에는 빗금(`repeating-linear-gradient` 135°), 가로줄(90°), 점선 윗선까지
**패턴 세 종류가 동시에** 있었다. 지금은 테두리 두 종류(실선 · 파선)뿐이다.
상태를 하나 더 표시해야 한다면 패턴을 늘리지 말고, 정말 막대 위에 있어야 하는
정보인지부터 다시 묻는다.

## 중복 인코딩은 의도된 것이다

높이와 명도가 **같은 변수(응답 수준)를 두 번** 나타낸다. 낭비가 아니라 목적이 있다.

- 막대가 짧을 때(수준 1) 높이만으로는 눈에 잘 안 들어오는데 명도가 보완한다.
- 명도를 구분하기 어려운 환경(색각 이상 · 저대비 화면 · 흑백 인쇄)에서는
  높이가 같은 정보를 그대로 대신한다.

그래서 **둘 중 하나만 남기지 않는다.** 명도만 쓰면 접근성을 잃고,
높이만 쓰면 짧은 막대를 읽기 어렵다.

## 범례

범례도 두 채널을 나눠 보여준다.

```
1단계 ▢▢▢▢ 4단계     ← 명도 눈금
▣ 필수 선결 조건        ← 실선 테두리
▤ 90일 검증            ← 파선 테두리
```

상태 다섯 개를 평면으로 나열하지 않는다. 그러면 명도와 테두리가 같은 종류의
구분인 것처럼 읽힌다.

## 상세 카드는 별개다

막대 아래 상세 카드(`.answer-question-detail--{status}`)는 **선택한 문항 하나**만
다루므로 다른 막대와 비교되지 않는다. 여기서는 상태별 색(`--chart-blocker` 등)을
왼쪽 테두리에 그대로 쓴다. 비교 맥락이 없으면 명도 순서 문제도 없다.

## 검증

`app/readiness-chart-colors.test.ts`가 강제한다.

- `--chart-level-1`~`4`의 **상대 휘도를 계산해** 수준이 오를수록 어두워지는지 확인한다.
  하나라도 역전되면 실패한다.
- `필수 선결 조건`·`90일 검증` 규칙에 `border: 2px`가 있고 `background`가 **없어야** 한다.
- 상세 카드는 상태별 색 토큰을 계속 쓴다.
- 옛 주황·갈색 계열 색이 되살아나면 실패한다.

`components/answer-question-chart.test.tsx`가 캡션과 막대 클래스를 확인한다.
